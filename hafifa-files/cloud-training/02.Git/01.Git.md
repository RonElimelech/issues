
### Goals
- The trainee will understand the basics of working with Git.
- The trainee will understand general Git etiquette (e.g., conventional commits, PR standards, etc.).

> During this section of the training, we'll be making extensive use of the official SCM book. Don't be daunted by its size; manage your time efficiently and, when possible, try to practice the concepts being taught.

> [SCM Book](https://git-scm.com/book/en/v2)

### Tasks

#### Chapter 1: Introduction
- Install and configure Git on your endpoint.
- What is Git, and how does it differ from other version control systems?
- Explain the benefits of using version control for collaborative projects.
- What are some common configuration settings you can adjust in Git?
- How can you view the Git configuration settings that have been applied?

#### Chapter 2: Git Basics
- Explain the different states of a file in Git (untracked, unmodified, modified, staged). What does each of them mean?
- Describe the purpose of the `.gitignore` file. How does it affect file tracking?
- Create a new private repository in GitHub and clone it to your endpoint.
- How can you add/remove/rename a file?
- Create a new branch named "text" in your repository and switch to it.
- Explain the difference between a local and remote repository.
- What happens when you run `git push` vs. `git push origin main`?
- Set the branch to track the main remote.
- Create a text file named "text.txt" in your repository, stage, and commit it.
- How can you view the commit ID of your latest commit?
- Are the committed changes present in your remote repository? If not, make it so they are.
- Amend the commit message of your latest commit; change it to "Sorry for forgetting this!".
- How can you view the status of your repository?
- Explain the difference between `git fetch` and `git pull`.
- What does `git log` do? How can you format its output for better readability?

#### Chapter 3: Branching and Merging
- How can you view the differences between two branches?
- What is a merge? How can you merge two branches?
- What is rebasing? Why is it useful?
- What is the difference between merging and rebasing, and when might you prefer one over the other?
- Start on `main`, create two branches: `branch-A` and `branch-B`.
- Switch to `branch-A` and add a new file "conflict-maker"; write "This will be fine" inside it and commit it.
- Switch to `branch-B` and add a new file "conflict-maker"; write "I'm creating a conflict" inside it and commit it.
- Switch to `branch-A` and run `git merge branch-B`. What happened? How can you solve it?
- After solving the conflict, push `branch-B` and switch to `main` and add a new file "conflict-maker"; write "I should be rebased", commit it, and push to main.
- Switch to `branch-B` and try pulling `origin/main`. What happened? How can you solve it?
- Explain what a fast-forward merge is and when it occurs.

#### Chapter 7 (7.1, 7.2, 7.3, 7.5, 7.6, 7.7, 7.14): Git Tools

### Goals
- The trainee will understand basic software operations and how Linux processes interact with system resources like CPU and memory.
- The trainee will gain a basic understanding of CPU and memory management in Linux, including concepts such as memory allocation and CPU utilization.
- The trainee will understand CPU throttling and Out-Of-Memory (OOM) kills, including how the Linux OS handles these conditions.
- The trainee will learn the differences between heap and stack memory, how they are used in software applications, and their roles in process management.
- The trainee will be proficient in using Linux troubleshooting tools for monitoring and diagnostics.
- The trainee will understand how to check key system information such as distribution version, kernel version, and hardware details using Linux commands.

> A solid grasp of Linux system fundamentals, particularly memory and CPU, is crucial for understanding system behavior and optimizing design. While these topics often lead to complex tangents, we urge you to stay focused and answer questions clearly and concisely. For example, if you're trying to understand concepts like a "self-referencing page table" and its value to the kernel, you're being too clever. Don't be clever.

### Tasks
- Read about the `free` command, run `free -h` and explain what each column represents. How does Linux balance memory usage?
- Read about memory swap, run `swapon --show` to check if swap space is being used. Why does Linux use swap? What happens when the system runs out of memory?
- Read about the Linux process address space. Why is it needed? Was there always a process address space?
- Read about physical and virtual memory, also read about paging (specifically two level paging) and answer the following questions:
  - What is the difference between physical and virtual memory?
  - What is the concept of paging? What problem does it aim to solve?
  - Bonus: Read about how virtual address translation work. What is the purpose of control register 3 (CR3)? What are the LSBs and MSBs of a virtual address used for and how do they aid in the translation process?
- Read about the concepts of stack and heap (in the context of Linux processes) and answer the following questions:
  - What are the differences between stack and heap?
  - Read about the `ulimit` command, how can you check the stack limit?
  - Bonus: What is a stack overflow? Why does it happen? What are ways to avoid it?
- Read about the Linux OOM Killer. What is it? Why is it useful?
- Bonus: In a previous section of the training, you've learned about the concept of Fork-bomb. Supposedly, the Linux OOM Killer should prevent such a case, try running one inside a VM and attempt to track the OOM killer's actions, did it manage to stop it? If not, why?
- Read about the concept of CPU and answer the following questions:
  - What is a CPU core?
  - What is a CPU thread?
  - Read about the `lscpu` command, run `lscpu` to list CPU details, such as architecture, number of cores and threads. Explain what multi-core processing means for system performance.
  - Read about CPU cycles and answer the following questions:
    - What is a CPU cycle?
    - What is CPU throttling? Why would it occur?
    - Read about the `cpulimit` command, try installing `cpulimit` and throttling a process to half a core.
- Read about the `top` command, run `top` to visualize and monitor system resources, focusing on CPU and memory usage by individual processes. What does each of the columns mean?
- Read about system load average and the `w` command and answer the following questions:
  - What is system load average?
  - Run `w`. What does each column represent?
- Read https://www.brendangregg.com/blog/2017-08-08/linux-load-averages.html to understand the load average fallacy.
- Read about the `df` and `du` commands, explain their differences.
- Run `df -h`. What does each column represent?
- Read about the `lsof` command and answer the following questions:
    - Explain the output of the command `lsof /bin/bash`
    - Open a new terminal and run `lsof /bin/bash` again, explain the differences between the two outputs
- Read about the `uname` command. How can you view operating system information? Extract the exact kernel version. 
- Bonus:
    - Read about the `strace` command and answer the following questions:
      - What is strace? Why is it usefu?
      - What metrics can be extracted from the output of strace?
